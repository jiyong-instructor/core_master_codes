# section06 오늘 배운 내용 정리

안녕하세요 여러분! 오늘은 프론트엔드에서 서버의 데이터를 받아오는 첫 API 실습을 진행했습니다. API로 받은 데이터를 화면에 그리고, 여러 페이지의 공통 영역을 어떻게 재사용할 수 있는지도 함께 비교해봤어요.

오늘 흐름은 이렇게 기억하면 좋아요.
**fetch로 요청하기 → JSON 데이터 꺼내기 → map으로 화면 만들기 → 공통 화면을 재사용 가능한 구조로 나누기**

## 1. fetch로 프로필 API 요청하기

`01-profile-api.html`에서는 버튼을 누르면 서버에서 사용자 프로필을 받아와 화면에 보여줬습니다.

```js
fetch("https://jsonplaceholder.typicode.com/users/1")
  .then((응답) => {
    if (응답.ok === false) {
      throw new Error("프로필을 불러오지 못했어요 ㅠ0 ㅠ")
    }
    return 응답.json()
  })
  .then((프로필) => {
    console.log(프로필)
  })
  .catch((에러) => {
    console.error(에러)
  })
```

- `fetch()`: 주소로 네트워크 요청을 보내요.
- 첫 번째 `.then()`: 서버가 보내준 응답 객체를 받아요.
- `응답.ok`: 요청이 정상적으로 처리됐는지 확인해요.
- `응답.json()`: 응답 본문을 자바스크립트에서 사용할 데이터로 변환해요.
- 두 번째 `.then()`: 변환이 끝난 실제 데이터를 받아요.
- `.catch()`: 요청이나 변환 과정에서 발생한 오류를 처리해요.

`fetch()`의 결과가 바로 프로필 객체인 것은 아닙니다. 먼저 응답 객체를 받고, `json()` 변환이 끝나야 원하는 데이터를 사용할 수 있어요.

## 2. 로딩·성공·실패 화면 나누기

프로필을 불러오는 동안에는 먼저 로딩 문장을 보여주고, 성공하면 프로필을, 실패하면 오류 메시지를 보여줬습니다.

```js
프로필보여주는곳.innerHTML = "인스타 프로필 불러오는 중..."
```

```js
프로필보여주는곳.innerHTML = `
  <h1>${프로필.name}</h1>
  <p>${프로필.email}</p>
  <p>${프로필.phone}</p>
  <p>${프로필.website}</p>
`
```

API 화면은 보통 다음 세 가지 상태를 생각하면 좋아요.

1. 데이터를 기다리는 **로딩 상태**
2. 데이터를 잘 받아온 **성공 상태**
3. 요청에 실패한 **에러 상태**

## 3. 강아지 API에서 이미지 한 장 받아오기

`02-dog-api.html`에서는 랜덤 강아지 이미지 API를 호출했습니다.

```js
fetch("https://dog.ceo/api/breeds/image/random")
  .then((받아온결과) => 받아온결과.json())
  .then((객체만뽑힌결과) => {
    const 이미지다운로드주소 = 객체만뽑힌결과.message

    document.getElementById("강아지보여주는곳").innerHTML = `
      <img src="${이미지다운로드주소}" width="300px" />
    `
  })
```

API마다 보내주는 데이터의 모양이 다릅니다. 이 API에서는 `message`에 이미지 주소가, `status`에 요청 상태가 들어있어요. 그래서 먼저 콘솔에서 전체 객체를 확인한 뒤 필요한 키를 꺼내는 습관이 중요합니다.

## 4. map으로 여러 API 데이터 그리기

`03-dog-api-map.html`에서는 강아지 이미지 5개의 주소를 배열로 받아 한 번에 화면에 그렸습니다.

```js
const 이미지다운로드주소들 = 객체만뽑힌결과.message

const 이미지HTML = 이미지다운로드주소들.map((주소) => `
  <img src="${주소}" width="300px" />
`).join("")

document.getElementById("강아지보여주는곳").innerHTML = 이미지HTML
```

전체 흐름은 다음과 같습니다.

1. API에서 이미지 주소 배열을 받아요.
2. `map()`으로 주소마다 `<img>` 태그를 만들어요.
3. `join("")`으로 태그 배열을 하나의 문자열로 합쳐요.
4. `innerHTML`로 화면에 넣어요.

Section02에서 배운 `map()`이 실제 API 데이터와 연결된 순간이에요!

## 5. 페이지를 복사해서 화면 나누기

`04-pagecopy1-diary.html`과 `04-pagecopy2-dog.html`에서는 일기 페이지와 강아지 페이지를 각각 만들고 버튼으로 이동했습니다.

```js
const 메뉴이동 = (내가클릭한것) => {
  switch (내가클릭한것) {
    case "일기클릭함":
      location.href = "./04-pagecopy1-diary.html"
      break
    case "강아지클릭함":
      location.href = "./04-pagecopy2-dog.html"
      break
  }
}
```

`location.href`에 주소를 넣으면 해당 페이지로 이동합니다. 이해하기 쉬운 방식이지만 배너, 내비게이션처럼 공통인 코드까지 각 HTML에 반복해서 작성해야 해요. 공통 영역을 수정할 때 여러 파일을 모두 바꿔야 한다는 불편함도 생깁니다.

## 6. iframe으로 한 영역의 페이지 바꾸기

`05-iframe1-index.html`에서는 배너와 내비게이션은 그대로 두고, `iframe` 안에 표시되는 페이지만 바꿨습니다.

```html
<iframe id="아이프레임" src="./05-iframe2-detail1.html"></iframe>
```

```js
document.getElementById("아이프레임").src = "./05-iframe3-detail2.html"
```

- `iframe`: 현재 HTML 안에 다른 HTML 문서를 보여주는 태그
- `src`: iframe 안에 보여줄 문서의 주소

페이지 전체를 이동하지 않고 특정 영역만 다른 문서로 바꿀 수 있어요. 다만 외부 사이트는 보안 정책에 따라 iframe 안에서 열리지 않을 수 있고, 부모 문서와 iframe 문서는 서로 다른 문서라는 점도 기억해주세요.

## 7. 컴포넌트처럼 화면 조각 분리하기

`06-component-main.html`, `06-component-diary.js`, `06-component-dog.js`에서는 메뉴별 HTML을 별도의 JavaScript 파일로 분리했습니다.

```js
const 일기메뉴 = `
  <p>일기 메뉴</p>
  <p>일기 메뉴</p>
  <p>일기 메뉴</p>
`
```

```js
const 강아지메뉴 = `
  <p>강아지 메뉴</p>
  <p>강아지 메뉴</p>
  <p>강아지 메뉴</p>
`
```

메인 HTML에서는 두 파일을 먼저 불러온 뒤, 클릭한 메뉴에 맞는 화면 조각을 넣었습니다.

```html
<script src="./06-component-diary.js"></script>
<script src="./06-component-dog.js"></script>
```

```js
document.getElementById("컴포넌트영역").innerHTML = 일기메뉴
```

이렇게 화면의 한 부분을 역할별로 분리하면 공통 배너와 내비게이션은 한 번만 작성하고, 바뀌는 내용만 교체할 수 있어요. 지금은 템플릿 문자열로 간단하게 연습했지만, 화면을 작은 단위로 분리하고 조립한다는 것이 컴포넌트 방식의 중요한 시작점입니다.

## 세 가지 화면 구성 방식 비교

| 방식 | 동작 | 특징 |
| --- | --- | --- |
| 페이지 복사 | HTML 페이지 전체 이동 | 이해하기 쉽지만 공통 코드가 반복돼요. |
| iframe | 현재 페이지 안에 다른 문서 표시 | 문서가 분리되고 외부 페이지는 차단될 수 있어요. |
| 화면 조각 분리 | 필요한 HTML만 현재 영역에 삽입 | 공통 화면을 유지하고 바뀌는 부분만 관리할 수 있어요. |

## 오늘의 핵심

1. `fetch()`로 서버에 데이터를 요청할 수 있어요.
2. 응답 객체는 `json()`으로 변환한 뒤 실제 데이터를 사용해요.
3. 로딩, 성공, 실패 상태를 나누면 사용자에게 현재 상황을 알려줄 수 있어요.
4. 배열로 받은 API 데이터는 `map()`과 `join("")`으로 화면에 그릴 수 있어요.
5. `location.href`는 다른 페이지로 이동하고, iframe의 `src`는 내부 문서를 바꿔요.
6. 공통 영역과 바뀌는 영역을 나누면 반복 코드를 줄일 수 있어요.
7. 화면을 작은 조각으로 분리해서 조립하는 생각이 컴포넌트의 시작이에요.
