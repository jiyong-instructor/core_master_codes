# section07 오늘 배운 내용 정리

안녕하세요 여러분! 오늘은 검색과 스크롤처럼 아주 자주 발생하는 이벤트를 다루고, 너무 많은 함수 실행과 API 요청을 줄여주는 **디바운스와 스로틀**을 배웠습니다.

오늘 흐름은 이렇게 기억하면 좋아요.
**입력값 검색하기 → 디바운스로 마지막 입력 기다리기 → 스크롤 위치 계산하기 → 스로틀로 실행 횟수 제한하기**

## 1. input 이벤트로 검색어 받아오기

`01-search.html`에서는 검색창에 글자를 입력할 때마다 검색 기능을 연결했습니다.

```html
<input
  type="text"
  placeholder="검색어를 입력하세요"
  oninput="검색기능(event)"
/>
```

```js
const 검색기능 = (event) => {
  const 내가검색한단어 = event.target.value
}
```

- `input` 이벤트: 입력창의 값이 바뀔 때마다 발생해요.
- `event.target`: 지금 입력 이벤트가 발생한 태그예요.
- `event.target.value`: 사용자가 입력한 현재 값이에요.

## 2. filter와 includes로 검색하기

브랜드 배열에서 검색어가 포함된 항목만 골라냈습니다.

```js
const 브랜드 = ["애플", "삼성", "엘지", "구글", "마이크로소프트"]

const 검색결과들 = 브랜드.filter((브랜드이름) =>
  브랜드이름.includes(내가검색한단어)
)
```

- `filter()`: 조건에 맞는 값만 모아 새로운 배열을 만들어요.
- `includes()`: 문자열 안에 원하는 글자가 들어있는지 확인해요.

검색 결과 배열은 `join("<br />")`으로 연결한 뒤 `innerHTML`을 이용해 화면에 보여줬습니다.

```js
document.getElementById("검색결과보여주는곳").innerHTML =
  검색결과들.join("<br />")
```

검색어가 빈 문자열이면 모든 문자열에 빈 문자열이 포함된 것으로 판단되어 전체 브랜드가 검색된다는 점도 직접 확인해보세요.

## 3. 디바운스로 마지막 입력 기다리기

검색창에 `애플`을 입력하면 입력 이벤트는 한 번이 아니라 `애`, `애ㅍ`, `애프`, `애플`처럼 계속 발생할 수 있습니다. 이벤트마다 검색이나 API 요청을 실행하면 불필요한 작업이 많아져요.

`01-search.html`과 `02-debouce-search-with-api.html`에서는 이전 타이머를 취소하고 마지막 입력 이후 1초가 지났을 때만 기능을 실행했습니다.

```js
let 타이머

const 검색기능 = (event) => {
  clearTimeout(타이머)

  타이머 = setTimeout(() => {
    const 내가검색한단어 = event.target.value
    console.log(내가검색한단어)
  }, 1000)
}
```

동작 순서는 다음과 같습니다.

1. 사용자가 글자를 입력해요.
2. 기존에 예약한 타이머를 `clearTimeout()`으로 취소해요.
3. 새로운 1초 타이머를 예약해요.
4. 1초 안에 다시 입력하면 또 취소하고 새로 예약해요.
5. 입력을 멈춘 뒤 1초가 지나면 마지막 기능만 실행돼요.

이처럼 이벤트가 연속으로 발생할 때 **마지막 이벤트 이후 일정 시간 기다렸다가 한 번 실행하는 방식**을 디바운스라고 합니다.

## 4. 디바운스와 API 검색 연결하기

`02-debouce-search-with-api.html`에서는 사용자가 입력한 고양이 태그를 이미지 주소에 넣었습니다.

```js
const 내가검색한단어 = event.target.value

document.getElementById("검색결과보여주는곳").innerHTML = `
  <img src="https://cataas.com/cat/${내가검색한단어}/says/hello" />
`
```

검색 API를 연결할 때 디바운스를 사용하면 사용자가 타이핑하는 모든 순간마다 요청하지 않고, 입력을 잠시 멈췄을 때 필요한 요청만 보낼 수 있어요.

실제 주소에 사용자 입력값을 넣을 때는 띄어쓰기나 특수문자가 안전하게 전달되도록 `encodeURIComponent()`로 변환하는 방법도 사용할 수 있습니다.

```js
const 안전한검색어 = encodeURIComponent(내가검색한단어)
```

## 5. 현재 스크롤 위치를 비율로 계산하기

`03-scroll.html`에서는 사용자가 전체 페이지의 몇 퍼센트까지 내려왔는지 계산했습니다.

```js
const 스크롤퍼센트 =
  document.documentElement.scrollTop /
  (document.documentElement.scrollHeight -
    document.documentElement.clientHeight)
```

- `scrollTop`: 현재 위에서부터 내려온 거리
- `scrollHeight`: 스크롤할 수 있는 전체 문서 높이
- `clientHeight`: 현재 화면에 보이는 높이
- `scrollHeight - clientHeight`: 실제로 스크롤 가능한 거리

계산 결과는 0부터 1 사이의 비율로 나와요. `0.7` 이상이면 전체 스크롤 가능한 거리의 70% 이상 내려왔다는 뜻입니다.

```js
if (스크롤퍼센트 >= 0.7) {
  document.getElementById("인스타홈화면").innerHTML += `
    <div class="인스타피드"></div>
  `
}
```

이 방식으로 사용자가 아래쪽에 도착하기 전에 새로운 피드를 미리 추가하는 무한 스크롤을 만들 수 있습니다.

## 6. 스크롤 이벤트가 너무 자주 실행되는 문제

스크롤 이벤트는 사용자가 조금만 움직여도 매우 자주 발생합니다. 70%를 넘은 상태에서 이벤트가 여러 번 발생하면 피드나 API 요청도 한꺼번에 여러 개 추가될 수 있어요.

그래서 다음 작업이 필요합니다.

- 일정 시간 동안 함수 실행 횟수 제한하기
- 이미 API 요청 중인지 확인하기
- 같은 데이터를 중복해서 불러오지 않기
- 더 불러올 데이터가 없으면 요청 멈추기

이번 예제에서는 이 중 실행 횟수를 제한하는 **스로틀**을 적용했습니다.

## 7. 스로틀로 일정 시간에 한 번만 실행하기

`04-throttle-scroll-with-api.html`에서는 타이머가 실행 중이면 `return`으로 함수를 바로 종료했습니다.

```js
let 타이머 = "아직실행안함"

window.addEventListener("scroll", () => {
  if (타이머 !== "아직실행안함") return

  타이머 = setTimeout(() => {
    타이머 = "아직실행안함"
  }, 500)

  // 스크롤 위치 계산과 API 요청
})
```

첫 번째 스크롤 이벤트가 실행되면 타이머가 등록됩니다. 그 뒤 0.5초 동안 발생하는 이벤트는 `return`으로 무시되고, 타이머가 초기화된 뒤에야 다음 이벤트가 다시 실행돼요.

이처럼 이벤트가 계속 발생하더라도 **정해진 시간 간격마다 최대 한 번씩 실행되도록 제한하는 방식**을 스로틀이라고 합니다.

## 8. 스로틀과 무한 스크롤 API 연결하기

스크롤이 70% 이상 내려오면 강아지 API에서 새 이미지를 가져와 화면 끝에 추가했습니다.

```js
fetch("https://dog.ceo/api/breeds/image/random")
  .then((받아온결과) => 받아온결과.json())
  .then((객체만뽑힌결과) => {
    document.getElementById("인스타홈화면").innerHTML += `
      <img
        src="${객체만뽑힌결과.message}"
        width="500"
        height="500"
        style="object-fit: cover; margin: 50px;"
      />
    `
  })
```

Section06에서 배운 `fetch()`와 오늘 배운 스크롤·스로틀이 연결된 예제입니다. 새 이미지가 추가되면 문서 높이도 늘어나기 때문에 사용자는 계속 아래로 스크롤할 수 있어요.

## 디바운스와 스로틀 비교

| 구분 | 디바운스 | 스로틀 |
| --- | --- | --- |
| 실행 기준 | 마지막 이벤트 후 일정 시간이 지났을 때 | 정해진 시간 간격마다 최대 한 번 |
| 잘 어울리는 곳 | 검색, 자동 저장, 입력 검증 | 스크롤, 마우스 이동, 화면 크기 변경 |
| 핵심 생각 | 입력이 끝날 때까지 기다리기 | 계속 실행되더라도 횟수 제한하기 |

검색은 사용자가 입력을 마친 뒤 실행하는 것이 자연스럽고, 스크롤은 움직이는 동안에도 일정 간격으로 위치를 확인해야 하므로 각각 디바운스와 스로틀이 잘 어울려요.

## 오늘의 핵심

1. `event.target.value`로 검색창의 현재 값을 가져올 수 있어요.
2. `filter()`와 `includes()`를 함께 사용해 검색 결과를 만들 수 있어요.
3. 디바운스는 마지막 이벤트 이후 기다렸다가 한 번 실행해요.
4. 스크롤 비율은 현재 거리와 전체 스크롤 가능 거리로 계산해요.
5. 스크롤 이벤트는 매우 자주 발생하므로 실행 횟수를 제어해야 해요.
6. 스로틀은 정해진 시간 간격마다 최대 한 번 실행해요.
7. 스로틀과 API를 연결하면 중복 요청을 줄인 무한 스크롤을 만들 수 있어요.
