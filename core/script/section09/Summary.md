# section09 오늘 배운 내용 정리

안녕하세요 여러분! 오늘은 자바스크립트의 최신 기능을 오래된 브라우저에서도 사용할 수 있게 도와주는 폴리필과, 더 많은 사람이 웹을 이용하게 만드는 웹 접근성, 검색엔진이 페이지를 이해하도록 돕는 SEO와 사이트맵을 배웠습니다.

오늘 흐름은 이렇게 기억하면 좋아요.
**브라우저 호환성 확인하기 → 폴리필로 기능 보완하기 → 사람에게 이해되는 HTML 만들기 → 검색엔진에도 구조와 주소 알려주기**

## 1. 자바스크립트와 브라우저 환경

`01-bbb.html`에서는 함수와 버튼 클릭 이벤트가 브라우저에서 실행되는 기본 흐름을 확인했습니다.

```js
const qqq = () => {
  alert("hello~~~")
}
```

```html
<button onclick="qqq()">click!!</button>
```

자바스크립트는 브라우저의 자바스크립트 엔진이 해석합니다. 같은 코드라도 최신 문법이나 API를 어느 버전부터 지원하는지는 브라우저마다 다를 수 있어요.

그래서 개발할 때는 다음 환경을 먼저 정하는 것이 중요합니다.

- 지원할 브라우저 종류
- 지원할 최소 버전
- PC와 모바일 운영체제
- 최신 기능이 없을 때 제공할 대체 동작

## 2. Array.at()과 최신 자바스크립트 기능

`02-js-cross-browsing-issue-at.html`에서는 배열의 마지막 값을 쉽게 꺼내는 `at()`을 사용했습니다.

```js
const 과일들 = ["사과", "바나나", "딸기"]

console.log(과일들.at(-1)) // 딸기
```

- `at(0)`: 첫 번째 값
- `at(1)`: 두 번째 값
- `at(-1)`: 뒤에서 첫 번째, 즉 마지막 값

이 기능을 지원하지 않는 환경에서는 기존 문법으로 같은 결과를 만들 수도 있어요.

```js
const 마지막과일 = 과일들[과일들.length - 1]
```

새 문법을 사용하기 전에는 대상 브라우저가 지원하는지 확인하고, 지원하지 않는다면 대체 문법이나 폴리필을 고려합니다.

## 3. 폴리필이란?

폴리필은 브라우저에 없는 최신 기능을 이전 환경에서도 비슷하게 사용할 수 있도록 채워주는 코드입니다.

```html
<script src="폴리필을-제공하는-주소"></script>
```

폴리필이 먼저 실행되어 필요한 기능을 추가하면 그다음 작성한 코드에서 최신 API를 사용할 수 있어요.

다만 모든 최신 문법과 기능을 폴리필할 수 있는 것은 아닙니다.

- `Array.at()` 같은 내장 메서드는 폴리필로 보완할 수 있어요.
- 문법 자체를 이전 문법으로 바꾸는 작업은 Babel 같은 트랜스파일러가 필요할 수 있어요.
- DOM이나 브라우저 기능은 완전히 같은 동작으로 구현하기 어려울 수도 있어요.

외부 폴리필 주소를 그대로 연결할 때는 서비스의 신뢰성, 보안, 버전 고정 여부도 함께 확인해야 합니다.

## 4. 웹 접근성이란?

`03-web-accessibility.html`에서는 이미지와 버튼에 의미를 전달하는 속성을 작성했습니다.

웹 접근성은 장애 여부, 사용하는 기기나 입력 방식과 관계없이 가능한 많은 사용자가 웹의 정보와 기능을 이용할 수 있도록 만드는 것입니다. 화면을 눈으로 보는 사용자뿐 아니라 스크린 리더, 키보드, 음성 입력을 사용하는 사용자도 함께 생각해야 해요.

## 5. 이미지의 alt 작성하기

정보를 전달하는 이미지에는 이미지의 의미를 설명하는 `alt`가 필요합니다.

```html
<img src="./00-image.jpg" alt="잔디밭에서 뛰어노는 강아지" />
```

- 이미지가 로드되지 않을 때 대체 문장으로 보여요.
- 스크린 리더가 이미지의 의미를 읽어줄 수 있어요.
- `강아지 사진`처럼 형식만 말하기보다 현재 화면에서 필요한 내용을 설명하면 좋아요.

장식용으로만 사용해서 읽을 필요가 없는 이미지는 빈 대체 텍스트를 사용할 수 있습니다.

```html
<img src="./장식선.png" alt="" />
```

`aria-hidden="true"`는 요소를 접근성 트리에서 숨깁니다. 중요한 정보나 조작 요소에 사용하면 보조 기술 사용자가 내용을 알 수 없으므로 장식용 요소에만 신중하게 사용해주세요.

## 6. 버튼의 이름과 ARIA

버튼은 가능하면 화면의 글자만으로 목적을 이해할 수 있게 작성하는 것이 가장 좋아요.

```html
<button>고객센터로 이동</button>
```

아이콘만 있어서 보이는 글자로 목적을 알 수 없다면 `aria-label`로 접근 가능한 이름을 제공할 수 있습니다.

```html
<button aria-label="검색하기">🔍</button>
```

`role`은 요소의 역할을 설명하지만 아무 문장이나 넣을 수 있는 속성은 아닙니다. `button`, `navigation`, `dialog`처럼 표준에서 정한 값만 사용해야 해요. 기본 `<button>`에는 이미 button 역할이 있으므로 같은 role을 다시 작성할 필요가 없습니다.

ARIA는 기본 HTML의 의미를 대신하는 첫 번째 선택이 아니라, 기본 태그만으로 의미를 충분히 전달하기 어려울 때 보완하는 도구라고 생각해주세요.

## 7. 시맨틱 태그로 페이지 구조 만들기

`03-web-seo.html`에서는 의미 없는 `div`만 사용하는 대신 역할이 담긴 시맨틱 태그로 쇼핑몰을 구성했습니다.

```html
<header>
  <h1>넥타이 쇼핑몰 No.1</h1>
  <nav>에르메스 | 구찌 | 루이비통</nav>
</header>

<main>
  <section>
    <h2>신상품</h2>
    <p>최신 넥타이 컬렉션을 만나보세요.</p>
  </section>
</main>

<footer>...</footer>
```

- `header`: 페이지나 영역의 머리말
- `nav`: 주요 이동 링크 영역
- `main`: 페이지의 핵심 콘텐츠
- `section`: 하나의 주제로 묶인 콘텐츠 영역
- `footer`: 페이지나 영역의 하단 정보

시맨틱 태그는 브라우저, 보조 기술, 검색엔진이 문서 구조를 이해하는 데 도움을 줍니다. 제목은 `h1`부터 문서의 단계에 맞게 내려가도록 작성하는 것도 중요해요.

## 8. SEO란?

SEO(Search Engine Optimization)는 검색엔진이 페이지의 내용과 구조를 잘 이해하고 적절한 검색 결과에 보여줄 수 있도록 개선하는 과정입니다.

기본적으로 다음 내용을 챙기면 좋아요.

- 페이지마다 내용을 잘 설명하는 `<title>` 작성
- 검색 결과 설명에 사용할 `meta description` 작성
- 의미 있는 제목과 본문 구성
- 실제 이동 가능한 `<a href="...">` 링크 사용
- 이미지의 목적에 맞는 `alt` 작성
- 모바일에서도 읽기 좋은 반응형 화면
- 빠른 로딩과 안정적인 사용자 경험

```html
<head>
  <title>신상품 넥타이 | 넥타이 쇼핑몰</title>
  <meta
    name="description"
    content="이번 달 새로 입고된 넥타이 컬렉션을 확인해보세요."
  />
</head>
```

SEO는 검색 순위를 보장하는 특별한 속성 하나가 아니라, 검색엔진과 사용자 모두 이해하기 좋은 페이지를 꾸준히 만드는 작업이에요.

## 9. sitemap.xml로 페이지 주소 알려주기

`03-sitemap.xml`에서는 검색엔진이 사이트의 주요 주소를 발견할 수 있도록 XML 형식의 사이트맵을 만들었습니다.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://www.example.com/</loc>
    <lastmod>2026-08-13</lastmod>
    <changefreq>monthly</changefreq>
    <priority>1.0</priority>
  </url>
</urlset>
```

- `<loc>`: 실제 페이지의 전체 주소
- `<lastmod>`: 마지막으로 의미 있게 수정된 날짜
- `<changefreq>`: 콘텐츠가 변경될 것으로 예상하는 주기
- `<priority>`: 같은 사이트 안에서의 상대적인 우선순위

사이트맵 표준의 `xmlns`는 `http://www.sitemaps.org/schemas/sitemap/0.9`를 사용합니다. `<changefreq>`와 `<priority>`는 검색엔진에 전달하는 참고 정보이며, 실제 크롤링 주기나 검색 순위를 보장하지는 않아요.

사이트맵은 페이지를 발견하도록 도와주지만, 내용의 품질이나 접근성을 대신해주지는 않습니다.

## 웹 접근성과 SEO 비교

| 구분 | 웹 접근성 | SEO |
| --- | --- | --- |
| 주요 목적 | 다양한 사용자가 정보와 기능을 이용하게 하기 | 검색엔진이 페이지를 이해하고 발견하게 하기 |
| 주요 대상 | 사용자와 보조 기술 | 검색엔진과 검색 사용자 |
| 대표 예시 | 키보드 사용, alt, label, 올바른 버튼 | title, description, 시맨틱 구조, 사이트맵 |
| 공통점 | 의미 있고 구조적인 HTML이 중요해요. | 의미 있고 구조적인 HTML이 중요해요. |

둘의 목적은 다르지만 올바른 HTML 구조, 설명이 있는 이미지, 이해하기 쉬운 콘텐츠처럼 서로 도움을 주는 부분이 많아요.

## 오늘의 핵심

1. 최신 자바스크립트 기능은 브라우저별 지원 범위를 확인해야 해요.
2. 폴리필은 브라우저에 없는 기능을 코드로 보완해요.
3. 정보성 이미지에는 상황에 맞는 `alt`를 작성해요.
4. ARIA는 기본 HTML만으로 의미를 전달하기 어려울 때 보완해서 사용해요.
5. 시맨틱 태그는 사용자, 보조 기술, 검색엔진이 구조를 이해하도록 도와줘요.
6. SEO를 위해 페이지별 제목, 설명, 콘텐츠 구조와 링크를 잘 작성해야 해요.
7. `sitemap.xml`은 검색엔진에 사이트의 주요 URL을 알려줘요.
