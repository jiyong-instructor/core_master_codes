# section10 오늘 배운 내용 정리

안녕하세요 여러분! 오늘은 사용자가 글자 굵기, 제목, 목록 같은 서식을 직접 적용할 수 있는 **웹 에디터**를 사용해봤습니다. 에디터에 작성한 내용을 HTML로 꺼내 저장하고, 다음 페이지에서 다시 보여주는 흐름까지 연결했어요.

오늘 흐름은 이렇게 기억하면 좋아요.
**에디터 라이브러리 불러오기 → 입력 영역 만들기 → 작성 내용을 HTML로 꺼내기 → localStorage에 저장하기 → 조회 페이지에 보여주기**

## 1. 웹 에디터란?

웹 에디터는 사용자가 HTML을 직접 작성하지 않아도 제목, 굵은 글자, 목록, 링크 같은 서식을 적용할 수 있게 도와주는 입력 도구입니다. 게시글, 자기소개, 상품 설명, 이메일 작성 화면에서 자주 볼 수 있어요.

이번 수업에서는 Quill이라는 에디터 라이브러리를 CDN으로 불러왔습니다.

```html
<link
  href="https://cdn.jsdelivr.net/npm/quill@2.0.3/dist/quill.snow.css"
  rel="stylesheet"
/>

<script src="https://cdn.jsdelivr.net/npm/quill@2.0.3/dist/quill.js"></script>
```

- CSS 파일: 툴바와 에디터의 기본 모양을 제공해요.
- JavaScript 파일: 글 작성, 서식 적용, 내용 추출 같은 기능을 제공해요.
- CDN: 설치하지 않고 외부 주소에서 라이브러리 파일을 불러와요.

CSS와 JavaScript 중 하나가 빠지면 모양이 깨지거나 기능이 동작하지 않을 수 있습니다.

## 2. 에디터가 들어갈 영역 만들기

`01-web-editor.html`에서는 일반 `div`를 에디터가 들어갈 영역으로 준비했습니다.

```html
<div id="editor">
  <p>Hello World!</p>
  <p>Some initial <strong>bold</strong> text</p>
  <p><br /></p>
</div>
```

div 안에 미리 작성한 HTML은 에디터가 시작될 때 보여주는 초기 내용이 됩니다.

- `<p>`: 문단
- `<strong>`: 중요한 굵은 글자
- `<br />`: 줄바꿈

## 3. Quill 인스턴스 만들기

에디터 영역을 만든 뒤 `new Quill()`로 실제 편집 기능을 연결했습니다.

```js
const quill = new Quill("#editor", {
  theme: "snow"
})
```

- 첫 번째 인자 `#editor`: 에디터로 사용할 요소의 CSS 선택자
- 두 번째 인자: 에디터 설정 객체
- `theme: "snow"`: Quill이 제공하는 Snow 테마 적용

이 코드가 실행되면 일반 div가 서식 툴바를 가진 편집 영역으로 바뀝니다.

## 4. 에디터 내용을 HTML로 가져오기

등록 버튼을 누르면 Quill에 작성한 내용을 꺼냈습니다.

```js
const 자기소개등록기능 = () => {
  const 자기소개 = quill.getSemanticHTML()
  console.log(자기소개)
}
```

`getSemanticHTML()`은 사용자가 작성한 서식이 포함된 내용을 의미 있는 HTML 문자열로 반환해요.

예를 들어 에디터에서 일부 글자를 굵게 만들었다면 다음과 같은 문자열을 받을 수 있습니다.

```html
<p>안녕하세요. 저는 <strong>프론트엔드 개발자</strong>입니다.</p>
```

일반 input의 `.value`로 글자를 가져오는 것과 달리, 웹 에디터에서는 글자와 서식 정보를 함께 다뤄야 한다는 점이 중요해요.

## 5. localStorage에 자기소개 저장하기

가져온 HTML 문자열은 localStorage에 저장했습니다.

```js
localStorage.setItem("자기소개", 자기소개)
```

- 첫 번째 인자 `"자기소개"`: 데이터를 찾을 때 사용할 키
- 두 번째 인자 `자기소개`: 저장할 HTML 문자열

localStorage는 문자열을 저장하므로 에디터에서 가져온 HTML 문자열을 그대로 넣을 수 있어요. 같은 출처의 다음 페이지에서도 같은 키로 꺼낼 수 있습니다.

저장이 끝나면 조회 페이지로 이동했습니다.

```js
location.href = "02-web-editor.html"
```

전체 등록 흐름은 다음과 같아요.

1. 사용자가 에디터에 자기소개를 작성해요.
2. 등록 버튼을 클릭해요.
3. 작성 내용을 HTML 문자열로 가져와요.
4. localStorage에 저장해요.
5. 조회 페이지로 이동해요.

## 6. 저장된 내용 다시 꺼내기

`02-web-editor.html`에서는 같은 키로 자기소개를 가져왔습니다.

```js
const 자기소개 = localStorage.getItem("자기소개")
```

저장된 값이 없으면 `getItem()`은 `null`을 반환해요. 실제 화면에서는 값이 없는 경우도 처리해주는 것이 좋습니다.

```js
const 자기소개 =
  localStorage.getItem("자기소개") ??
  "아직 등록된 자기소개가 없습니다."
```

`??`는 왼쪽 값이 `null` 또는 `undefined`일 때 오른쪽 기본값을 사용하는 연산자입니다.

## 7. innerHTML로 서식까지 보여주기

저장한 내용은 HTML 태그가 포함된 문자열이기 때문에 `innerHTML`로 화면에 넣었습니다.

```js
document.getElementById("상자").innerHTML = 자기소개
```

`innerText`를 사용하면 `<strong>` 같은 태그도 글자로 보일 수 있지만, `innerHTML`은 문자열 안의 태그를 실제 HTML로 해석해서 굵은 글자와 문단 같은 서식을 화면에 표현해요.

## 8. innerHTML과 보안 주의하기

사용자가 작성한 HTML을 그대로 `innerHTML`에 넣으면 원하지 않는 태그나 속성이 함께 실행될 위험이 있습니다. 이를 XSS(Cross-Site Scripting)라고 해요.

```js
// 개념 예시: 검증된 정화 과정을 거친 HTML만 화면에 넣어요.
const 안전한HTML = HTML정화도구.sanitize(자기소개)
상자.innerHTML = 안전한HTML
```

실제 서비스에서는 다음을 꼭 생각해주세요.

- 에디터에서 허용할 서식만 제한하기
- 저장하거나 출력하기 전에 HTML 정화(sanitize)하기
- 서버에서도 입력값을 다시 검증하기
- 사용자 입력 HTML을 무조건 신뢰하지 않기

이번 예제처럼 내가 직접 작성한 내용을 내 브라우저에서 연습하는 것과 여러 사용자의 글을 서비스에 보여주는 것은 보안 위험이 다릅니다.

## 9. localStorage와 실제 서버 저장의 차이

이번 수업에서는 저장 흐름을 쉽게 연습하기 위해 localStorage를 사용했습니다.

| 구분 | localStorage | 서버·데이터베이스 |
| --- | --- | --- |
| 저장 위치 | 현재 사용자의 브라우저 | 서비스의 서버 |
| 다른 기기에서 조회 | 어려워요 | 로그인 등을 통해 가능해요 |
| 사용자가 데이터 삭제 | 쉽게 가능해요 | 서비스 정책에 따라 관리해요 |
| 적합한 예시 | 개인 설정, 임시 연습 데이터 | 게시글, 회원 정보, 공유 데이터 |

실제 게시글 등록 기능에서는 보통 에디터 내용을 API로 서버에 전송하고 데이터베이스에 저장합니다.

## 오늘의 핵심

1. 웹 에디터는 사용자가 서식이 있는 글을 쉽게 작성하도록 도와줘요.
2. Quill의 CSS와 JavaScript를 모두 불러와야 모양과 기능을 사용할 수 있어요.
3. `new Quill()`로 일반 div에 에디터 기능을 연결해요.
4. `getSemanticHTML()`로 작성 내용과 서식을 HTML 문자열로 가져올 수 있어요.
5. HTML 문자열은 localStorage에 저장하고 다음 페이지에서 꺼낼 수 있어요.
6. 서식이 포함된 문자열은 `innerHTML`로 화면에 표현해요.
7. 사용자 HTML을 출력할 때는 XSS를 막기 위한 정화와 검증이 필요해요.
